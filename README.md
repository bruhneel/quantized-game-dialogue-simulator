# Quantized Game Dialogue Simulator

[![Built with askThili](https://ask.thili.ai/api/v1/public/projects/rcxwvusdev/badge.svg)](https://ask.thili.ai/b/rcxwvusdev)

This project, "Quantized Game Dialogue Simulator," helps game developers understand how to optimize language models for in-game dialogue. You will build and quantize a small GPT, then simulate its performance on resource-constrained devices, providing insights into memory and speed trade-offs.

## What you are building

**Goal.** You will build a small, quantized GPT model trained on game dialogue, then simulate its memory footprint and generation speed to demonstrate its suitability for resource-constrained game devices.

**Done when.** The project is complete when you have trained a small GPT on a custom game dialogue corpus, applied both dynamic and static post-training quantization, and provided measurements comparing the original and quantized model sizes and simulated inference speeds.

## Milestones

Tick these off as you go, and commit after each one.

- [ ] **1. Prepare a small game dialogue text corpus.**  
      Hint: Focus on cleaning and tokenizing your text data.
- [ ] **2. Implement a basic GPT architecture and train it on the corpus.**  
      Hint: Apply techniques from the 'Build GPT from Scratch' drill.
- [ ] **3. Generate sample dialogue from the trained GPT.**  
      Hint: Use the trained model for text generation.
- [ ] **4. Apply dynamic and static post-training quantization to the model.**  
      Hint: Refer to the 'Shrink a Neural Network with Quantisation' drill.
- [ ] **5. Measure and compare the original and quantized model sizes.**  
      Hint: Calculate the memory footprint of model weights.
- [ ] **6. Simulate inference speed by comparing operations on original versus quantized weights.**  
      Hint: Estimate computational cost based on data types.

## Run it

You need Python 3.12 and git.

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # then choose a model; see the comments inside
python -m app.cli hello
pytest
```

Your work goes in `app/core.py` (one stub per milestone) and `tests/test_core.py`. The first tests pass already; they
check the plumbing.

## Settings and secrets

Model settings live in `.env`, which is ignored by git. **Never commit `.env` or paste a key into code.** If a key ever
reaches GitHub, treat it as leaked and make a new one.
